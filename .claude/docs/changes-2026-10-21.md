## 3. Fixed entity/DB schema mismatches

These bugs broke `GET /form043/{userId}/user` and `GET /schedules/{doctorId}` (a 500 inside the server that surfaced as 403).

| File | Problem | Fix |
|---|---|---|
| `Form043Entity` | `conditionOfMucosaPeriodontium` and `externalExaminations` were mapped to the wrong columns; `birthDate` was a String | `@Column(name = "condition_of_oral_mucosa_periodontium")`, `@Column(name = "external_examination")`, `birthDate` → `Instant` |
| `CreateForm043Dto`, `Form043ResponseDto` | `birthDate` was a String | `Instant` (`@NotNull`) |
| `SchedulesEntity` | `dayOfWeek` was read as an ordinal number; no getters/setters; ID used `IDENTITY` | `@Enumerated(STRING)` + `NAMED_ENUM`, `@Getter/@Setter`, `GenerationType.UUID` |
| `SchedulesExceptionsEntity` | `@Table(name = "schedules_entity")`; no getters/setters; ID used `IDENTITY` | `schedules_exceptions`, `@Getter/@Setter`, `GenerationType.UUID` |
| `SchedulesExceptionsRepository` | Native queries used the tables `schedule_exceptions`/`schedule_exception` and the column `isDayOff` | `schedules_exceptions`, `is_day_off` |
| `SchedulesExceptionsMapper` | `isDayOff` was not mapped | `@Mapping(target = "isDayOff", source = "dayOff")` |
| `FileTransferEntity` | `status` had no enum annotations | `@Enumerated(STRING)` + `NAMED_ENUM` |
| `ServicesType` (Java) | Missing the DB value `SCAN` | Added `SCAN` |

## 4. New migration: `V8_align_enums_with_java.sql`

Aligns the DB enums with the Java enums (Java is treated as the source of truth):

- `services_type`: renamed `BRACER` → `BRACKET`
- `appointment_status`: added `PENDING_PAYMENT`
- `file_type`: `{PDF, JPEG, PNG, STL}` → `{IMAGE, ARCHIVE, MODEL_3D, DOCUMENT, PDF}`. Existing rows are converted: JPEG/PNG → IMAGE, STL → MODEL_3D
- `file_purpose`: removed `BRACER`; existing rows move to `BRACKET`
